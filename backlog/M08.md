## Contexto
Existe um rascunho em `docs/gramatica.md` e a especificação está fechada ({{M02}}).

## Tarefa
Transformar o rascunho na gramática final, pronta para parsing descendente (LL(1)):

```
programa → { comando } EOF
comando  → decl | atrib | print | if | while | bloco
decl     → "var" ID ":" tipo "=" expr ";"
tipo     → "int" | "bool"
atrib    → ID "=" expr ";"
print    → "print" "(" expr ")" ";"
if       → "if" "(" expr ")" bloco [ "else" bloco ]
while    → "while" "(" expr ")" bloco
bloco    → "{" { comando } "}"
expr     → soma [ ( "==" | "!=" | "<" | ">" | "<=" | ">=" ) soma ]
soma     → termo { ( "+" | "-" ) termo }
termo    → fator { ( "*" | "/" ) fator }
fator    → NUM | "true" | "false" | ID | "(" expr ")" | "-" fator
```

1. Ajustar ao que está na especificação e explicar a notação (`{}`, `[]`, `|`).
2. Documentar por que não há ambiguidade: um não terminal por nível de precedência; árvores de `1 + 2 * 3` e `1 - 2 - 3` (só uma possível para cada).
3. Mostrar a eliminação da recursão à esquerda (`soma → soma "+" termo | termo` ⇒ `soma → termo { "+" termo }`) e que o laço preserva a associatividade à esquerda.
4. Tabela FIRST das alternativas de `comando` e de `fator`, mostrando que são disjuntas.
5. Registrar as decisões: chaves obrigatórias eliminam o *else pendente*; comparação não associativa (`a < b < c` é erro sintático).
6. Uma derivação mais à esquerda completa de um programa válido curto.

## Critérios de aceite
- [ ] Gramática final em `docs/gramatica.md`
- [ ] Tabela FIRST de `comando` e `fator`
- [ ] Árvores/justificativa de precedência e associatividade
- [ ] Uma derivação à mão documentada

## Desafio opcional
Onde entrariam `&&`, `||` e `!` na hierarquia? Justifique com a árvore de `!a || b && c`.
