## Contexto
O lexer produz `Vec<Token>` terminado em `Eof` ({{M04}}), a AST está definida em `src/ast.rs` ({{M10}}) e as mensagens de erro esperadas estão no banco de casos ({{M09}}). `src/parser.rs` está vazio.

## Tarefa
Base do parser e toda a parte de expressões. Cada não terminal da gramática vira um método.

1. `ErroSintatico { mensagem }` com `Display` e `std::error::Error`.
2. `Parser::new(tokens)` e os utilitários:
   - `atual(&self) -> &Token` (sem consumir)
   - `verificar(&self, tipos: &[TipoToken]) -> bool`
   - `consumir(&mut self) -> Token` (nunca passa do `Eof`)
   - `esperar(&mut self, tipo, msg) -> Result<Token, ErroSintatico>` — se não casar, erro no formato
     `"{linha}:{coluna}: erro sintático: {msg}, encontrado '{lexema ou EOF}'"`
3. Expressões, devolvendo `Expr` com `linha` do operador:
   - `expr → soma [ op_comparacao soma ]` (com `if`, não `while`: comparação não associativa)
   - `soma → termo { (+|-) termo }` e `termo → fator { (*|/) fator }` com **laço** (associatividade à esquerda; nada de recursão à esquerda)
   - `fator → NUM | true | false | ID | "(" expr ")" | "-" fator`; qualquer outro token → `"expressão esperada"`
   - `NUM` que não cabe em `i64` → erro sintático `"número muito grande"`
4. Um método público temporário `expressao(&mut self) -> Result<Expr, ErroSintatico>` para testar isoladamente (pode virar privado em {{M12}}).

## Critérios de aceite
- [ ] Teste `precedencia`: `1 + 2 * 3` → raiz `+`, filho direito `*`
- [ ] Teste `associatividade_esquerda`: `10 - 3 - 2` → raiz `-` com filho esquerdo `-`
- [ ] Testes de unário (`- -4`), parênteses e `expressão esperada` em `1 + ;`
- [ ] Todo caminho do parser consome um token ou devolve erro (sem laço infinito)
- [ ] `cargo test --lib parser` passa

## Fora do escopo
Comandos e `programa()` ({{M12}}).
