## Contexto
O lexer reconhece todos os tokens válidos (#4) e o CLI tem `--tokens` (#5). Hoje um caractere fora do alfabeto não gera mensagem.

## Tarefa
1. **Antes de mexer**, rode `cargo test` e confirme que tudo passa — esses testes são a regressão desta issue.
2. No lexer, quando nenhum padrão casar: registrar `"{linha}:{coluna}: erro léxico: caractere inválido '{c}'"` em `erros`, descartar o caractere e **continuar**. O programador recebe todos os erros de uma vez.
3. No CLI (com ou sem `--tokens`): se `lexer.erros()` não for vazio, imprimir todos em stderr e sair com código 1.
4. Criar `exemplos/erro_lexico.mk` com pelo menos dois caracteres inválidos em linhas diferentes.
5. Depois do merge, criar e publicar a tag `v0.1-lexer` em `main`.

## Critérios de aceite
- [ ] `Lexer::new("x @ y")` → tokens `[Id, Id, Eof]` e `erros() == ["1:3: erro léxico: caractere inválido '@'"]`
- [ ] ≥ 3 novos testes de erro (um erro, vários erros em linhas diferentes, erro no fim do arquivo)
- [ ] `cargo run -q -- exemplos/erro_lexico.mk` lista todos os erros e `echo $?` dá 1
- [ ] Testes anteriores continuam passando
- [ ] Tag `v0.1-lexer` publicada

## Desafio opcional
Uma segunda versão do lexer usando a crate `regex` com grupos nomeados, rodando a mesma suíte. Anote a comparação no README.

### Como saber que está pronta
`cargo run -q -- exemplos/erro_lexico.mk` imprime erros léxicos em stderr e sai com código 1; `git tag -l v0.1-lexer` não é vazio

Ao terminar: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` sem falhas, PR com `Closes` desta issue e revisão de outro membro.
