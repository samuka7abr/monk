## Contexto
A gramática final está em `docs/gramatica.md` (#8). As pastas `tests/casos/validos/` e `tests/casos/invalidos/` existem e estão vazias.

## Tarefa
Criar os programas que o teste automático de #13 vai rodar.

**Válidos** (≥ 8) em `tests/casos/validos/*.mk`, cobrindo: precedência (`var x: int = 1 + 2 * 3 - -4;`), parênteses, aninhamento de `while` e `if`, `if` sem `else`, blocos soltos `{ }`, programa vazio, comentários, todos os operadores de comparação.

**Inválidos** (≥ 8) em `tests/casos/invalidos/*.mk`. Cada arquivo testa **um único** erro e a 1ª linha é um comentário com o trecho da mensagem esperada:

| Conteúdo | 1ª linha |
|---|---|
| `var x int = 1;` | `// ERRO: esperado ':'` |
| `x = 1 + ;` | `// ERRO: expressão esperada` |
| `if x > 1 { }` | `// ERRO: esperado '('` |
| `print(x)` | `// ERRO: esperado ';'` |
| `while (x) { x = x - 1;` | `// ERRO: esperado '}'` |
| `1 = x;` | `// ERRO: comando inesperado` |
| `var b: bool = (1 + 2;` | `// ERRO: esperado ')'` |
| `var 1x: int = 0;` | `// ERRO: esperado identificador` |

Os inválidos devem ser **lexicamente** válidos (o erro é sintático). Inclua também `var b: bool = 1 < 2 < 3;` com `// ERRO: esperado ';'` (a comparação não é associativa: depois de `1 < 2` o parser espera `;` e encontra `<`).

As mensagens acima viram o contrato do parser (#11, #12): o texto depois de `// ERRO: ` precisa aparecer na mensagem do `ErroSintatico`.

## Critérios de aceite
- [ ] ≥ 8 válidos e ≥ 8 inválidos
- [ ] Todo inválido com 1ª linha `// ERRO: ...` e um único erro
- [ ] Um `README.md` curto em `tests/casos/` explicando a convenção

---
### Como saber que está pronta
≥ 8 arquivos em `tests/casos/validos/` e ≥ 8 em `tests/casos/invalidos/`, todo inválido com 1ª linha `// ERRO: ...`

Ao terminar: `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` sem falhas, PR com `Closes` desta issue e revisão de outro membro.
