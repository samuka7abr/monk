## Contexto
O gerador produz `Vec<Instr>` para qualquer programa válido (#20). `src/vm.rs` está vazio. Como cada fase só recebe entrada válida, a VM pode confiar que variáveis existem e tipos batem.

## Tarefa
1. Estado: `codigo`, `mem: HashMap<String, Valor>`, `rotulos: HashMap<String, usize>` (montado numa **pré-passagem** sobre os `Label`), contador `executadas`.
2. Laço buscar → avançar (`pc += 1`) → decodificar → executar, enquanto `pc < codigo.len()`:
   - `Label`: não executa nem conta
   - `Copia`, `Neg`, `Print`, `Goto` (`pc = rotulos[..]`), `IfFalse` (salta se `false`), `Bin` (aritmética e comparação)
3. Semântica: `i64` com `wrapping_add/sub/mul/neg`; `/` truncando para zero (nativo do Rust; use `wrapping_div`). Divisão por zero → `ErroExecucao { mensagem: "linha {l}: erro de execução: divisão por zero" }`.
4. `executar(&mut self, saida: &mut dyn FnMut(&Valor))`: a saída é injetável — no CLI imprime, nos testes empurra para um `Vec`. Booleanos são impressos como `true`/`false`.
5. `executadas()` conta instruções realmente executadas (rótulos não contam) — é a métrica do "antes" da otimização.
6. Leitura de nome inexistente na memória é bug do compilador: `panic!` com mensagem clara (não é erro do usuário).

## Critérios de aceite
- [ ] Teste `fatorial`: saída `[Int(120)]`
- [ ] Teste `if_else` (`x = 3; if (x > 5) print 1 else print 0` → `[0]`)
